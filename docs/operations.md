# Установка и эксплуатация

## Требования

- Docker Desktop (Mac/Windows) или Docker + Compose (Linux).
- Ключи API с https://my.telegram.org/apps (одни на команду).
- Доступ в интернет к серверам Telegram.

## Конфигурация (`.env`)

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `TG_API_ID` | да | — | api_id приложения Telegram |
| `TG_API_HASH` | да | — | api_hash приложения Telegram |
| `POSTGRES_PASSWORD` | да | `tg` | пароль базы в Docker; задайте свой до первого запуска |
| `DATABASE_URL` | без Docker | — | адрес Postgres, если запускаете через `run.sh` |
| `TZ_NAME` | нет | `Europe/Minsk` | часовой пояс рабочих часов и дневного счётчика |
| `ALLOWED_HOSTS` | при доступе по домену | `127.0.0.1,localhost` | по каким адресам открывается панель, через запятую (`*` — любые) |
| `SECURE_COOKIES` | за HTTPS | `0` | `1` — cookie входа только по HTTPS |
| `SECRET_KEY` | нет | создаётся сам | ключ подписи входа; иначе хранится в `data/secret_key` |
| `DATA_DIR` | нет | `./data` | где хранить сессии Telegram и ключ |

Пользователи, лимиты аккаунтов и правила команды хранятся в базе и меняются в панели.

## Запуск

```bash
docker compose up -d --build     # или двойной клик по start.command на Mac
docker compose logs -f tg-sender # логи
docker compose restart tg-sender # перезапуск (например, после правки .env)
docker compose down              # остановить (данные сохраняются)
```
- Панель: http://127.0.0.1:8000. Порт открыт **только локально**, Postgres наружу не открыт вовсе.
- Папка `app/` смонтирована в контейнер, uvicorn запущен с `--reload`: **правки кода применяются без пересборки**. Пересборка (`--build`) нужна при изменении `requirements.txt` или `Dockerfile`.
- Схема базы обновляется сама при запуске: применяются новые файлы `app/migrations/NNN_*.sql`.

### На сервере (24/7)
1. Скопируйте проект, заполните `.env` (обязательно свой `POSTGRES_PASSWORD`).
2. `docker compose up -d --build`, откройте панель и создайте админа.
3. Доступ — через SSH-туннель: `ssh -L 8000:127.0.0.1:8000 user@server`, затем http://127.0.0.1:8000.
   Или через reverse proxy (nginx или Caddy) с HTTPS: впишите домен в `ALLOWED_HOSTS`, включите `SECURE_COOKIES=1`
   и передавайте в прокси исходный заголовок `Host` — панель принимает формы только со своего адреса.
4. **Не открывайте порт 8000 в интернет без HTTPS.**

## Данные и бэкапы

```
Postgres (том pgdata)  — пользователи, аккаунты, лиды, кампании, переписка, журнал
data/sessions/acc_N.session — сессии Telegram (= доступ к аккаунтам!)
data/secret_key        — ключ подписи входа в панель
```

- **Бэкап базы:** `docker compose exec postgres pg_dump -U tg tg > backup.sql`
- **Восстановление:** `docker compose exec -T postgres psql -U tg tg < backup.sql` (в пустую базу).
- **Бэкап сессий:** скопируйте папку `data/`. Храните её так же надёжно, как пароли.
- **Перенос на другой сервер:** `backup.sql` + папка `data/` — повторный вход в Telegram не понадобится.

## Безопасность

- Файлы `data/sessions/*.session` дают **полный доступ к аккаунтам Telegram** команды. Не передавайте их, не кладите в облако или git. `.gitignore` уже исключает `data/` и `.env`.
- Сессию панели видно в Telegram: Настройки → Устройства (устройство «TG Sender Panel»). Там же её можно завершить.
- Если сотрудник уходит: админ отключает его в «Команде», сам сотрудник (или админ) нажимает «Выйти» у его аккаунтов. Лиды остаются закреплены за этими аккаунтами.
- Пароли хранятся в виде scrypt-хэшей. Смена пароля завершает остальные входы пользователя.
- Панель принимает POST-запросы только со своих страниц (проверка `Origin`/`Referer`) и только по адресам из `ALLOWED_HOSTS`: чужой сайт, открытый в браузере, не может запустить рассылку.

## Обновление

```bash
git pull
docker compose up -d --build
```

### Переход с однопользовательской версии (SQLite)
Старая база `data/sender.db` не переносится: при переходе в ней не было данных, которые стоило бы сохранять. Сессия Telegram переносится: при создании админа файл `data/account.session` подключается как его первый аккаунт.

## Тесты

```bash
scripts/test.sh                                   # поднимет Postgres, создаст базу tg_test и прогонит тесты
SAMPLE_XLSX=path/to/list.xlsx scripts/test.sh     # + тест на реальном файле списка
scripts/test.sh -k team                           # только часть тестов
```
Тесты не обращаются к Telegram: используется имитация клиента. База `tg_test` пересоздаётся при каждом прогоне.
