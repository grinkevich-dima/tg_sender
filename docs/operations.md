# Установка и эксплуатация

## Требования

- Docker Desktop (Mac/Windows) или Docker + Compose (Linux), **либо** Python 3.11+.
- Ключи API с https://my.telegram.org/apps.
- Доступ в интернет к серверам Telegram.

## Конфигурация (`.env`)

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `TG_API_ID` | да | — | api_id приложения Telegram |
| `TG_API_HASH` | да | — | api_hash приложения Telegram |
| `PANEL_USER` | нет | `admin` | логин панели (HTTP Basic) |
| `PANEL_PASSWORD` | на сервере — да | пусто (без пароля) | пароль панели |
| `TZ_NAME` | нет | `Europe/Minsk` | часовой пояс рабочих часов и дневного счётчика |
| `DATA_DIR` | нет | `./data` | где хранить базу и сессию |
| `ALLOWED_HOSTS` | при доступе по домену | `127.0.0.1,localhost` | по каким адресам открывается панель, через запятую (`*` — любые) |

Остальные настройки (лимиты, паузы, стоп-слова) хранятся в базе и меняются в панели.

## Запуск

### Docker на своём компьютере
```bash
docker compose up -d --build     # или двойной клик по start.command на Mac
docker compose logs -f           # логи
docker compose restart           # перезапуск (например, после правки .env)
docker compose down              # остановить
```
- Панель: http://127.0.0.1:8000. Порт открыт **только локально**.
- `restart: unless-stopped` — контейнер поднимается вместе с Docker.
- Папка `app/` смонтирована в контейнер, uvicorn запущен с `--reload`: **правки кода применяются без пересборки**.
- Пересборка (`--build`) нужна только при изменении `requirements.txt` или `Dockerfile`.

### Без Docker
```bash
./run.sh          # создаст .venv, поставит зависимости, запустит на 127.0.0.1:8000
PORT=8080 ./run.sh
```

### На сервере (24/7)
1. Скопируйте проект, заполните `.env`, **обязательно задайте `PANEL_PASSWORD`**.
2. `docker compose up -d --build`.
3. Доступ к панели — через SSH-туннель:
   `ssh -L 8000:127.0.0.1:8000 user@server`, затем http://127.0.0.1:8000.
   Или через reverse proxy (nginx или Caddy) с HTTPS и паролем. Тогда впишите домен в `ALLOWED_HOSTS`
   и передавайте в прокси исходный заголовок `Host` — панель принимает формы только со своего адреса.
4. **Не открывайте порт 8000 в интернет без HTTPS и пароля.**

## Данные и бэкапы

```
data/
  account.session     — сессия Telegram (= доступ к аккаунту!)
  sender.db (+ -wal, -shm) — база: контакты, шаблоны, кампании, списки, журнал, настройки
```

- **Бэкап:** остановите контейнер (`docker compose stop`) и скопируйте папку `data/` целиком.
- **Перенос на другой компьютер:** скопируйте проект вместе с `data/` — повторный вход не понадобится.
- **Не открывайте `sender.db` другими программами, пока панель запущена** (SQLite в режиме WAL).

## Безопасность

- `data/account.session` даёт **полный доступ к вашему Telegram**. Не передавайте его, не кладите в облако или git. `.gitignore` уже исключает `data/` и `.env`.
- Активную сессию панели видно в Telegram: Настройки → Устройства (устройство «TG Sender Panel»). Там же её можно завершить.
- Если сессия могла утечь — завершите её в Telegram и удалите `data/account.session`.
- Панель принимает POST-запросы только со своих страниц (проверка `Origin`/`Referer`) и только по адресам из `ALLOWED_HOSTS`: чужой сайт, открытый в браузере, не может запустить рассылку.

## Обновление

```bash
git pull
docker compose up -d --build
```
Схема базы обновляется автоматически при запуске: новые таблицы и колонки добавляются, данные сохраняются.

## Тесты

```bash
pip install -r requirements-dev.txt     # Python 3.12, как в Dockerfile
python -m pytest tests -q
SAMPLE_XLSX=path/to/list.xlsx python -m pytest tests -q   # + тесты на реальном файле списка
```
Тесты не обращаются к Telegram: используется имитация клиента.
