# TG Sender: персональные рассылки тёплой аудитории в Telegram

Веб-панель для команды: люди регистрируются на ваши вебинары и семинары и вступают в вашу группу Telegram, а менеджеры пишут им персональные сообщения **от своих личных аккаунтов**. Панель собирает аудиторию в сегменты, следит за лимитами, закреплением лидов, отписками и ответами.

Стек: Python, [Telethon](https://docs.telethon.dev) (MTProto), FastAPI, Postgres. Запуск — Docker Compose.

## Что умеет

| Функция | Как работает |
|---|---|
| Команда | Вход по логину и паролю. Роли: **админ** (всё видит, добавляет людей, задаёт правила) и **менеджер** (свои аккаунты и кампании). |
| Аккаунты | Каждый менеджер подключает свой Telegram (QR-код или код + 2FA). У каждого аккаунта свои лимиты, прогрев, рабочие часы и паузы. |
| Сегменты | Именованные списки лидов для кампаний: **участники своих групп**, CSV, контакты и диалоги Telegram, теги. У участников групп сохраняются `{group}` и `{joined}` для персонализации. |
| Поиск групп | Публичные группы по ключевым словам и месту (включая группы обсуждения каналов) и проверка списков ссылок; оценка 0–100 по теме, живости и размеру; статусы «интересна / вступил / отклонена». |
| Лиды | Общая база: импорт из Telegram, CSV и xlsx. Дубликаты по ID, username и телефону объединяются. Лид **закрепляется за одним аккаунтом** — коллеги ему не пишут. |
| Кампании | По шаблону (со спинтаксом и переменными) или из готового списка xlsx, где у каждой строки свой текст. Фильтры, очередь «чат → с диалогом → без диалога», распределение по аккаунтам: знакомые люди достаются тем, кто с ними переписывался. |
| Правила команды | Отписка стоп-словом действует на всю команду. Одному человеку нельзя писать чаще раза в N дней, из какой бы кампании ни было. |
| Защита аккаунтов | `FloodWait` и `PEER_FLOOD` ставят на паузу только тот аккаунт, которого они коснулись; его лиды остаются за ним. |
| Ответы и отчёты | Ответы сохраняются и видны на дашборде. Статусы *в очереди → доставлено → прочитано → ответил*, ошибки с причиной, отчёт CSV. |

## Быстрый запуск (Docker)

```bash
cp .env.example .env      # впишите TG_API_ID, TG_API_HASH, POSTGRES_PASSWORD
docker compose up -d --build
```

Откройте **http://127.0.0.1:8000**, создайте админа и подключите аккаунт Telegram. Подробно — в [быстром старте](docs/quickstart.md).

На Mac можно дважды кликнуть `start.command`.

## Структура

```
app/
  main.py         — сборка приложения
  auth.py         — пользователи, роли, вход, защита форм
  tg.py           — аккаунты Telegram: вход, поиск адресата, «Найти получателей», ответы и прочтения
  worker.py       — отправка: у каждого аккаунта своя очередь, лимиты и паузы
  campaigns.py    — кампании: xlsx и шаблоны, фильтры, очередь, распределение по аккаунтам
  leads.py        — лиды: дубликаты, импорт, отписка
  db.py           — Postgres: пул, запросы, миграции (app/migrations/*.sql)
  web/            — страницы панели по разделам
data/             — сессии Telegram и ключ входа (не публиковать!)
tests/            — тесты с Postgres и имитацией Telegram
```

## Ответственность

Даже тёплой аудитории пишите персонально: напоминайте, где вы познакомились (вебинар, семинар, группа), давайте способ отказаться. Жалобы «Спам» — главная причина ограничений Telegram. Массовые нежелательные рассылки нарушают [правила Telegram](https://telegram.org/tos); ответственность — на владельцах аккаунтов.
