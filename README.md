# TG Sender: рассылка по своим контактам в Telegram

Веб-панель для рассылки сообщений от **личного аккаунта** Telegram. В ней можно работать с шаблонами, прогревать аккаунт, смотреть отчёты о доставке и прочтении.

Стек: Python, [Telethon](https://docs.telethon.dev) (MTProto), FastAPI, SQLite. Всё работает одним процессом, данные лежат в папке `data/`.

📚 **Документация:** [docs/](docs/README.md) — [быстрый старт](docs/quickstart.md) · [руководство](docs/user-guide.md) · [формат xlsx](docs/xlsx-format.md) · [прогрев и лимиты](docs/limits.md) · [частые проблемы](docs/troubleshooting.md) · [эксплуатация](docs/operations.md) · [архитектура](docs/architecture.md)

## Что умеет

| Функция | Как работает |
|---|---|
| Авторизация | Вход в панели **по QR-коду** (Telegram на телефоне → Настройки → Устройства → Подключить устройство) или номер → код → облачный пароль (2FA). Сессия сохраняется в `data/account.session`. |
| Контакты | Импорт из записной книжки Telegram, из всех личных диалогов или из CSV. Можно назначать теги. Колонки CSV, кроме стандартных, становятся переменными шаблона. |
| Шаблоны | Переменные `{first_name}`, `{name}`, `{company}` и любые другие. Спинтакс `{Привет\|Здравствуйте}`. Можно проверить шаблон отправкой в «Избранное». |
| Кампании | Шаблон + контакты (все или по тегу). Можно не отправлять тем, кто уже получил этот шаблон. Есть пауза, продолжение, повтор ошибок. |
| Отчёты | Статусы: *в очереди → доставлено → прочитано → ответил*, отдельно *ошибка* (с причиной) и *пропущено*. Отчёт выгружается в CSV (открывается в Excel). |
| Списки из xlsx | Загрузка готового списка обращений (у каждой строки свой текст, ссылка `web.telegram.org/a/#ID` или `t.me/…`, тема форума, «ты/вы», история общения, статус). Фильтры, очередь «чат → человек с диалогом → без диалога», сверка «есть ли диалог» с реальным Telegram, кнопка «▶ отправить сейчас» для тестов, отчёт CSV. |
| Прогрев | Дневной лимит растёт постепенно: по умолчанию 10 → +5 в день → потолок 50. Паузы между сообщениями случайные, 45–150 сек. Отправка только в рабочие часы. |
| Защита аккаунта | При `FloodWait` система ждёт указанное Telegram время. При `PEER_FLOOD` все кампании встают на паузу на 24 ч. Тех, кто ответил стоп-словом («стоп», «отписаться»…), система исключает автоматически. |

## Установка (Mac)

1. Зайдите на **https://my.telegram.org/apps**, войдите по номеру и создайте приложение (название любое). Скопируйте `api_id` и `api_hash`.
2. Распакуйте архив и запустите в терминале:
   ```bash
   cd tg-sender
   ./run.sh          # при первом запуске создаст .env и остановится
   ```
3. Откройте `.env` и впишите `TG_API_ID`, `TG_API_HASH`. На сервере обязательно задайте ещё `PANEL_PASSWORD`.
4. Снова выполните `./run.sh` и откройте **http://127.0.0.1:8000**.
5. Нажмите «Войти», введите номер и код, который придёт в Telegram.

Панель должна быть запущена, пока идёт рассылка. Если закрыть терминал, отправка остановится. После повторного запуска она продолжится с того же места.

### Через Docker на Mac

Двойной клик по `start.command` — соберёт и запустит контейнер (лог — в `start.log`).
Папка `app/` смонтирована в контейнер с автоперезагрузкой: правки кода подхватываются без пересборки
(пересборка нужна только при изменении `requirements.txt`).

### На сервере (VPS), чтобы работало 24/7
```bash
cp .env.example .env   # заполнить, обязательно PANEL_PASSWORD
docker compose up -d --build
```
Порт открыт только на `127.0.0.1`. Заходить через SSH-туннель: `ssh -L 8000:127.0.0.1:8000 user@server`, потом открыть http://127.0.0.1:8000. Или поставить nginx/Caddy с HTTPS — тогда впишите домен в `ALLOWED_HOSTS` в `.env` и не переписывайте заголовок `Host` в прокси (панель принимает формы только со своего адреса).

## Рекомендации, чтобы аккаунт не ограничили

- **Пишите тем, кто вас знает.** Лучше всего импортировать людей через «Записную книжку» или «Личные диалоги». Первое сообщение незнакомому человеку — главная причина `PEER_FLOOD`.
- **Username и телефоны из CSV.** Поиск по username в Telegram ограничен (примерно сотни в день). По телефону найти можно только тех, кто есть в ваших контактах. Остальные получат статус «получатель не найден».
- **Не торопитесь с прогревом.** Если аккаунт новый или раньше не делал рассылок, держите 10–20 сообщений в день первую неделю.
- **Используйте спинтакс.** Когда у всех получателей одинаковый текст, это похоже на спам.
- **Добавьте в текст способ отписаться**, например «ответьте «стоп», если не актуально». Одна жалоба «Спам» вредит аккаунту больше, чем десяток неотправленных сообщений.
- **Если пришёл `PEER_FLOOD`,** напишите [@SpamBot](https://t.me/SpamBot), подождите и снизьте лимиты.
- Массовые нежелательные рассылки нарушают [правила Telegram](https://telegram.org/tos). Ответственность за использование на владельце аккаунта.

## CSV-формат

См. `contacts_example.csv`. Нужна хотя бы одна из колонок: `username` (можно `@name` или ссылкой t.me), `phone`, `user_id`. Разделитель запятая, точка с запятой или Tab. Кодировка UTF-8.

## Структура

```
app/
  main.py        — веб-панель (маршруты)
  tg.py          — аккаунт Telegram: вход, импорт, события прочтения/ответов, хуки входящих
  worker.py      — очередь отправки, прогрев, лимиты, обработка ошибок
  templating.py  — переменные и спинтакс
  outreach.py    — списки из xlsx: импорт, фильтры, очередь
  xlsx.py        — чтение .xlsx без сторонних библиотек
  db.py          — SQLite
data/            — база и сессия (не публиковать!)
tests/           — тесты с мок-клиентом (Python 3.12): pip install -r requirements-dev.txt && python -m pytest tests
```

## Бэклог: ИИ-ответы (Claude)

В `app/tg.py` уже есть точка расширения `incoming_hooks`. Каждое входящее личное сообщение передаётся туда вместе с контактом. Варианты подключения:

1. **Через личный аккаунт (userbot)** — хук из `incoming_hooks` вызывает Claude API и отвечает `event.reply(...)`. Нужны белый список чатов, задержка «как у человека» и ручной режим «предложить ответ, отправить после подтверждения».
2. **Через Telegram Business-бота (нужен Premium)** — официальный способ. Бот подключается к личному аккаунту и отвечает от вашего имени в выбранных чатах. Работает отдельно от рассылки, поэтому риск для аккаунта минимальный.
